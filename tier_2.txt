  - Common Query Anti-Patterns
    - SELECT *: fetching unnecessary columns, defeating index-only scans
    - Implicit type cast in WHERE clause disabling index use
    - Function wrapping indexed column: WHERE date(created_at) = '...' instead of range
    - LIKE with leading wildcard: WHERE name LIKE '%foo' (no B-tree)
    - NOT IN with NULLs: logical trap causing no rows returned
    - Unnecessary DISTINCT masking incorrect JOIN multiplicity
    - OR on different columns preventing index use (use UNION ALL instead)
    - Mutable functions in WHERE clause called per row (use immutable)
    - Large IN lists: rewrite as JOIN to VALUES or temp table
    - OFFSET with large values: full scan to skip rows (use keyset pagination)
    - UPDATE with correlated subquery: rewrite as UPDATE FROM
    - ORDER BY with non-deterministic expression causing unstable plans
    - Unbounded recursive CTE (missing termination or cycle check)
    - Multiple COUNT(DISTINCT col): separate passes, use HLL if approximate OK

- Indexing

  - Index Types
    - B-tree
      - Default index type
      - Supports: =, <, <=, >, >=, BETWEEN, IN, LIKE 'foo%', IS NULL, IS NOT NULL
      - Does not support: LIKE '%foo', regular expressions
      - Index structure: balanced tree, leaf pages contain heap pointers
      - Fill factor tuning for UPDATE-heavy tables
      - Deduplication (PostgreSQL 13+): space saving for duplicate entries
    - Hash
      - Supports equality (=) only
      - When to prefer over B-tree (equality-only lookups, large keys)
      - Hash indexes not WAL-logged before PG 10 (now safe)
      - Cannot be used for range scans or ordering
    - GiST (Generalized Search Tree)
      - Geometric types, ranges, full-text search, nearest neighbor
      - PostGIS spatial indexes
      - Range type overlap and containment queries
      - Nearest neighbor (<->) operator support
    - SP-GiST (Space-Partitioned GiST)
      - Non-balanced tree structures
      - IP addresses, phone numbers, geometric points
      - When SP-GiST outperforms GiST
    - GIN (Generalized Inverted Index)
      - Full-text search (tsvector, tsquery)
      - Array containment (@>, <@, &&)
      - JSONB key/value existence and containment
      - fastupdate: buffered insert mode for GIN
      - gin_pending_list_limit: flush threshold
      - GIN vs GiST for full-text: GIN faster reads, GiST faster builds
    - BRIN (Block Range Index)
      - Very small index for naturally ordered large tables
      - Time-series data: created_at, event_time columns
      - pages_per_range tuning
      - BRIN correlated with physical storage order
      - Summarization: manual brin_summarize_range() vs autosummarize
      - BRIN vs B-tree: when BRIN is appropriate
    - Bloom Filter Index
      - Probabilistic multi-column equality queries
      - Small index size, false positive rate tunable
      - Requires bloom extension
      - Use cases: tables with many equality filter columns

  - Index Design Principles
    - Single-column vs composite (multi-column) indexes
    - Column ordering in composite indexes (most selective first for point queries, query prefix for range scans)
    - Index selectivity analysis (n_distinct, most_common_vals)
    - Index-only scans: include all needed columns, visibility map must be clean
    - INCLUDE columns in B-tree indexes (PostgreSQL 11+): non-key columns for covering
    - Partial indexes: WHERE clause to index subset of rows
      - Partial index for soft deletes (WHERE deleted_at IS NULL)
      - Partial index for status filters (WHERE status = 'active')
      - Partial index for non-null columns
    - Expression indexes (functional indexes)
      - Index on lower(email) for case-insensitive lookup
      - Index on date_trunc('day', created_at) for date range queries
      - Index on (data->>'key') for JSONB key extraction
      - Index on array_length(tags, 1) for array size filtering
    - Unique indexes: enforcing uniqueness, partial unique indexes
    - Index on foreign key columns: preventing full table lock during parent DELETE
    - Covering index strategy: eliminate heap fetch for common queries
    - Indexes on expressions with immutable functions only
    - Descending indexes and mixed ASC/DESC composite indexes

  - Index Maintenance
    - REINDEX: offline rebuild (table lock)
    - REINDEX CONCURRENTLY: online rebuild (PostgreSQL 12+)
    - REINDEX DATABASE CONCURRENTLY: all indexes in database online
    - Monitoring index bloat: pgstattuple, pgstatindex
    - pgstatindex: avg_leaf_density, leaf_fragmentation
    - Index fill factor: reduce bloat on UPDATE-heavy indexes
    - Detecting invalid indexes: SELECT * FROM pg_indexes WHERE ... (indisvalid)
    - Dropping and recreating invalid index after failed CONCURRENTLY
    - pg_repack: online table and index bloat reduction
    - Index rebuild after pg_upgrade (collation changes)
    - Duplicate index detection: same columns, same order, same predicate
    - Unused index detection: pg_stat_user_indexes.idx_scan = 0
    - Index usage tracking: resetting pg_stat_user_indexes after deployments
    - CLUSTER: physically reorder table by index (heavy operation)
    - Autovacuum role in keeping visibility map clean for index-only scans

  - Indexing for Specific Patterns
    - Full-text search indexing
      - tsvector column: generated column approach
      - GIN index on tsvector
      - ts_rank and ts_rank_cd for ranking
      - to_tsvector, to_tsquery, plainto_tsquery, websearch_to_tsquery
      - Text search configuration (dictionaries, stop words, stemming)
      - Multilingual full-text search
    - JSONB indexing
      - GIN index on whole JSONB column (containment, key existence)
      - B-tree expression index on extracted key: ((data->>'key')::int)
      - GIN with jsonb_path_ops vs default (size vs operator support)
      - jsonpath queries and indexing (PostgreSQL 12+ jsonb_path_query)
    - Array indexing
      - GIN index for array containment (@>, <@, &&)
      - B-tree index on array element via expression index (unnest)
    - Range type indexing
      - GiST index for range containment, overlap
      - SP-GiST for range types in some cases
    - UUID indexing
      - B-tree on UUID primary key (random inserts cause bloat)
      - UUID v7 (time-ordered) vs UUID v4 (random) for index efficiency
      - fill_factor tuning for UUID primary keys
    - Time-series indexing
      - BRIN on timestamp column (naturally ordered data)
      - Partitioning by time range + B-tree on timestamp within partition
      - Composite index (tenant_id, created_at) for multi-tenant time queries
    - Multi-tenant indexing
      - Composite indexes with tenant_id as first column
      - Partial indexes per tenant (impractical at scale, better: composite)
      - Row-level security with index selectivity

  - Index Monitoring and Diagnostics
    - pg_stat_user_indexes: idx_scan, idx_tup_read, idx_tup_fetch
    - pg_statio_user_indexes: idx_blks_read, idx_blks_hit (cache hit per index)
    - pgstattuple(index): tuple count, free space, dead tuple count
    - pgstatindex(index): tree depth, leaf density, fragmentation
    - Identifying indexes never used since last stats reset
    - Identifying indexes with low selectivity (high idx_tup_read / idx_scan)
    - Monitoring index build progress: pg_stat_progress_create_index
    - Identifying index bloat beyond fill_factor
    - Confirming index is used by target query via EXPLAIN ANALYZE
    - Hypothetical indexes via hypopg extension (test index without building)

- Database and System Tuning

  - Memory Configuration
    - shared_buffers
      - Recommended: 25% of RAM (starting point)
      - Too low: high blks_read, low cache hit ratio
      - Too high: OS page cache crowded, OOM risk
      - Diminishing returns above 8-16GB in most workloads
    - effective_cache_size
      - Planner estimate of OS page cache available
      - Recommended: 50-75% of total RAM
      - Does not allocate memory, only influences planner cost model
      - Too low: planner avoids index scans unnecessarily
    - work_mem
      - Per sort/hash operation (not per session)
      - Total potential: max_connections * max_parallel_workers_per_gather * work_mem
      - Too low: excessive disk spill (temp files in pgsql_tmp)
      - Too high: OOM with many concurrent sessions
      - Set globally conservatively, override per session for analytical workloads
      - SET LOCAL work_mem = '256MB' for specific queries
    - maintenance_work_mem
      - Used by VACUUM, CREATE INDEX, ALTER TABLE ADD FOREIGN KEY, CLUSTER
      - Recommended: 256MB-2GB for large tables
      - Higher = faster VACUUM and index builds
      - autovacuum_work_mem: separate limit for autovacuum workers
    - temp_buffers
      - Per-session buffer for temporary tables
      - Increase for sessions heavily using temporary tables
    - wal_buffers
      - WAL write buffer (default: 1/32 of shared_buffers, max 64MB)
      - Increase to 64MB for high-write workloads
    - huge_pages
      - huge_pages = on: use Linux huge pages for shared memory
      - Reduces TLB pressure on large shared_buffers
      - Requires vm.nr_hugepages configured in /etc/sysctl.conf
      - huge_page_size (PG 14+): 2MB or 1GB huge pages

  - WAL and Checkpoint Configuration
    - wal_level: minimal / replica / logical (production: replica or logical)
    - synchronous_commit: on / off / local / remote_write / remote_apply
      - off: async commit, up to wal_writer_delay data loss risk
      - local: synchronous to local disk, async to standby
      - on: synchronous to primary and synchronous standbys
    - wal_writer_delay: WAL writer flush interval (default 200ms)
    - wal_writer_flush_after: WAL flush when buffer exceeds threshold
    - commit_delay: group commit delay (add small delay to batch commits)
    - commit_siblings: minimum concurrent transactions to trigger commit_delay
    - checkpoint_timeout: max time between checkpoints (default 5min)
    - max_wal_size: max WAL to accumulate before forced checkpoint (default 1GB)
    - min_wal_size: minimum WAL retained to avoid recycling
    - checkpoint_completion_target: spread writes over fraction of checkpoint interval (0.9)
    - wal_compression: compress full-page writes in WAL
    - full_page_writes: must be on for crash safety with in-place update storage
    - wal_sync_method: fsync, fdatasync, open_sync, open_datasync (OS-dependent)
    - max_wal_senders: max concurrent WAL streaming connections
    - wal_keep_size: minimum WAL retained for standby reconnect

  - Autovacuum Tuning
    - autovacuum = on (never disable in production)
    - autovacuum_max_workers: increase for high-table-count or busy databases (3-6)
    - autovacuum_naptime: sleep between workers (default 1min; reduce for busy systems)
    - autovacuum_vacuum_threshold: minimum dead tuples to trigger vacuum (default 50)
    - autovacuum_vacuum_scale_factor: fraction of table size (default 0.2; reduce for large tables to 0.01-0.05)
    - autovacuum_analyze_threshold: minimum changed tuples for analyze (default 50)
    - autovacuum_analyze_scale_factor: fraction for analyze (default 0.1)
    - autovacuum_vacuum_cost_limit: I/O throttle limit (default 200; increase to 400-800 for fast storage)
    - autovacuum_vacuum_cost_delay: sleep between cost limit hits (default 2ms; reduce to 0-1ms on NVMe)
    - autovacuum_freeze_max_age: max age before forced wraparound vacuum (default 200M)
    - autovacuum_multixact_freeze_max_age: same for multixact IDs
    - Per-table autovacuum overrides: ALTER TABLE ... SET (autovacuum_vacuum_scale_factor = 0.01)
    - autovacuum_work_mem: memory for each autovacuum worker (-1 uses maintenance_work_mem)
    - Monitoring autovacuum via pg_stat_activity and pg_stat_progress_vacuum
    - Wraparound emergency vacuum: understand age(relfrozenxid) thresholds

  - Connection and Process Configuration
    - max_connections: total client + replication + superuser connections
    - superuser_reserved_connections: reserve for emergency DBA access (3-5)
    - Connection pooling as the correct solution for high concurrency (not max_connections)
    - pgbouncer pool_mode: session / transaction / statement
    - pgbouncer max_client_conn, pool_size, reserve_pool_size
    - pgbouncer server_idle_timeout, client_idle_timeout
    - max_prepared_transactions: for two-phase commit (0 if not used)
    - deadlock_timeout: wait before deadlock detection (default 1s)
    - lock_timeout: maximum wait for a lock (set on role or session for protection)
    - statement_timeout: maximum query execution time
    - idle_in_transaction_session_timeout: kill sessions stuck in transaction
    - tcp_keepalives_idle, tcp_keepalives_interval, tcp_keepalives_count: prevent ghost connections

  - I/O and Storage Tuning
    - random_page_cost: cost of random page read (default 4.0; set to 1.1-1.5 for SSD/NVMe)
    - seq_page_cost: cost of sequential page read (default 1.0)
    - effective_io_concurrency: concurrent I/O requests for bitmap heap scan (200 for SSD)
    - maintenance_io_concurrency: concurrent I/O for maintenance operations (PG 13+)
    - wal_sync_method selection per OS and storage
    - Separate pg_wal to dedicated SSD/NVMe
    - Separate pg_log to dedicated partition (avoid log filling PGDATA)
    - Separate tablespaces for hot tables on faster storage
    - XFS vs ext4 filesystem choice for PGDATA
    - XFS: better for large sequential writes (WAL), noatime mount option
    - ext4: reliable, barriers on (never disable)
    - Disabling atime updates (relatime or noatime mount option)
    - I/O scheduler: deadline or noop/none for SSDs (avoid CFQ)
    - vm.dirty_ratio and vm.dirty_background_ratio tuning
    - vm.swappiness: reduce to 1-10 to prevent swap usage
    - Transparent Huge Pages: disable for PostgreSQL (performance regression)
    - NUMA architecture: numactl binding PostgreSQL to specific node

  - OS-Level Tuning
    - Kernel parameters: vm.overcommit_memory, vm.overcommit_ratio
    - Open file descriptors: ulimit -n (65536 minimum)
    - Max processes: ulimit -u for postgres user
    - POSIX shared memory: kernel.shmmax, kernel.shmall
    - Semaphores: kernel.sem (SEMMSL, SEMMNS, SEMOPM, SEMMNI)
    - TCP settings: net.core.somaxconn, net.ipv4.tcp_max_syn_backlog
    - Network buffer tuning for replication
    - CPU frequency scaling: set to performance governor
    - NUMA balancing: numactl --interleave for balanced memory
    - cgroups: isolate PostgreSQL CPU/memory/I/O on shared servers
    - Avoiding swap: disable or configure vm.swappiness appropriately
    - Checking BIOS power management (disable C-states for latency-sensitive workloads)

  - JIT Compilation
    - jit = on (default PostgreSQL 12+)
    - jit_above_cost: minimum query cost to apply JIT
    - jit_optimize_above_cost: minimum cost to apply full JIT optimization
    - jit_inline_above_cost: minimum cost to enable function inlining
    - When JIT helps: complex analytical queries with many expressions
    - When JIT hurts: OLTP queries (compilation overhead > savings)
    - Disabling JIT per session: SET jit = off
    - Monitoring JIT: EXPLAIN ANALYZE shows JIT compilation time

  - Partitioning for Performance
    - Range partitioning: time-based, ID-based
    - List partitioning: discrete value sets (country, status)
    - Hash partitioning: even distribution for load balancing
    - Partition pruning: constraint_exclusion and partition pruning at plan time
    - Dynamic partition pruning (PG 11+): runtime partition elimination
    - Partition-wise joins: joining two partitioned tables partition-by-partition
    - Partition-wise aggregates: aggregate per partition then combine
    - Declarative partitioning vs inheritance-based (legacy)
    - Default partition: catch-all for unmatched values
    - Attaching / detaching partitions: ALTER TABLE ATTACH PARTITION
    - pg_partman: automated time and serial partition management
    - Indexing partitioned tables: local indexes vs global indexes (no true global in PG)
    - Foreign keys to/from partitioned tables (PG 12+)
    - Partition pruning verification via EXPLAIN ANALYZE

  - Connection Pooling Tuning
    - pgbouncer architecture: single process, async I/O
    - Pool modes compared: session / transaction / statement
    - Transaction pooling: most scalable, limits on SET, prepared statements
    - Session pooling: safest, least scalable (1:1 server connection per client)
    - Statement pooling: autocommit only, very restrictive
    - pgbouncer pool_size per database-user pair
    - pgbouncer reserve_pool_size: burst handling
    - pgbouncer server_lifetime: recycle idle server connections
    - pgbouncer server_idle_timeout: idle server connection cleanup
    - pgbouncer client_idle_timeout: drop idle clients
    - pgbouncer max_db_connections: global cap per database
    - pgbouncer online reload: RELOAD command without restart
    - pgbouncer with PgBouncer-RR for query routing
    - pgpool-II: connection pooling + load balancing + query routing
    - Odyssey: multi-threaded connection pooler alternative

  - Performance Benchmarking
    - pgbench: built-in benchmark tool
      - pgbench -i: initialize test database
      - pgbench -c clients -j threads -T duration -P interval
      - Custom pgbench scripts for workload simulation
      - TPS (transactions per second) measurement
      - Latency measurement (average, percentile)

RELIABILITY

- High Availability Architecture

  - HA Concepts and Terminology
    - RTO (Recovery Time Objective): maximum tolerable downtime
    - RPO (Recovery Point Objective): maximum tolerable data loss
    - Failover: automatic or manual promotion of standby to primary
    - Switchover: planned, controlled primary change (zero data loss)
    - Warm standby: standby applies WAL continuously, ready to promote
    - Hot standby: standby accepts read queries while in recovery
    - Cold standby: standby not running, started only on failure
    - Split-brain: two nodes both acting as primary simultaneously
    - STONITH: fencing mechanism to prevent split-brain
    - Quorum: minimum nodes needed for decision (DCS-based systems)
    - VIP (Virtual IP): floating IP that moves with primary
    - Consensus: distributed coordination protocol (Raft, Paxos)

  - Streaming Replication Setup
    - Configuring wal_level = replica on primary
    - Configuring max_wal_senders and max_replication_slots
    - Creating replication user (REPLICATION privilege)
    - pg_hba.conf: replication entries for standby IP
    - primary_conninfo in standby: host, port, user, password, application_name
    - standby.signal file creation on standby (PG 12+)
    - pg_basebackup: initial standby creation
      - pg_basebackup -h primary -U replicator -D /data -P -R --wal-method=stream
      - --write-recovery-conf flag for automatic primary_conninfo generation
    - recovery.conf (PG 11 and earlier) vs postgresql.conf + standby.signal (PG 12+)
    - hot_standby = on: enable read queries on standby
    - Verifying streaming: pg_stat_replication on primary
    - Verifying receiver: pg_stat_wal_receiver on standby
    - Synchronous replication configuration

  - Logical Backup and Restore
    - pg_dump
      - Plain SQL format (-F p): human-readable, no parallel restore
      - Custom format (-F c): compressed, supports parallel restore
      - Directory format (-F d): parallel dump, one file per table
      - Tar format (-F t): portable
      - Schema-only dump (--schema-only)
      - Data-only dump (--data-only)
      - Single table dump (-t tablename)
      - Single schema dump (-n schemaname)
      - Exclude table data (--exclude-table-data)
      - Include large objects (--blobs, default on)
      - Consistent snapshot: uses single transaction (--serializable-deferrable for truly consistent)
      - Parallel dump (-j): multiple worker processes
      - Compression level (--compress=level)
      - No owner (--no-owner), no privileges (--no-acl) options
    - pg_dumpall
      - Dumps all databases + global objects (roles, tablespaces)

    - pg_restore
      - Restoring from custom or directory format

      - --no-owner, --no-acl
      - Single table restore (-t tablename)

      - --disable-triggers: allow data load without FK checks
      - --use-set-session-authorization vs --no-owner
      - Handling restore errors: continue vs stop
    - pg_dump for cross-version migration
      - Always dump from source, restore to target
      - Extension availability on target
      - Collation compatibility check
    - Logical backup limitations
      - Not suitable for PITR

  - pg_upgrade for Major Version Migration
    - Pre-upgrade checklist
      - Check all extensions are available in new version
      - Run pg_upgrade --check: dry run validation
      - Review pg_upgrade documentation for version-specific notes
      - Take full backup before upgrade
      - Test upgrade on non-production first
      - Verify application compatibility with new version
      - Check for removed/changed functions or behaviors
    - pg_upgrade execution
      - pg_upgrade -b old_bin -B new_bin -d old_data -D new_data -o '-c config_file=...' -O '-c config_file=...'
      - --link mode: hard link files (fast, old cluster unusable after)
      - --clone mode: copy-on-write clone (fast, filesystem support required)
      - Copy mode: full data copy (safe, double disk space)
    - Post-upgrade tasks
      - Run analyze_new_cluster.sh (update statistics)
      - Run delete_old_cluster.sh (remove old data after validation)
      - Reindex all indexes (collation may have changed)
      - Update extensions: SELECT pg_catalog.pg_extension_config_dump(...)
      - Verify application functionality
      - Update monitoring dashboards for new metrics
    - Logical replication based major version upgrade (zero-downtime)
      - Set up logical replication from old version to new version
      - Synchronize data
      - Cutover with minimal downtime (application reconnect)
    - pg_upgrade limitations
      - Cannot upgrade if logical replication slots exist
      - Cannot upgrade if old cluster has unlogged tables (in some cases)
      - pg_upgrade does not upgrade extensions automatically

  - Failover and Switchover Procedures
    - Planned switchover (Patroni)
      - patronictl switchover --master <node> --candidate <node>
      - Verify application traffic moves to new primary
      - Verify old primary demoted to replica
      - Verify replication resumes on all members
    - Unplanned failover (Patroni automatic)
      - Patroni detects leader failure via DCS TTL expiry
      - Most eligible standby promoted (lowest lag, highest priority)
      - VIP moved, HAProxy updated
      - Old primary fenced or isolated (watchdog STONITH)
    - Manual failover without Patroni
      - Identify most up-to-date standby (pg_stat_replication replay_lsn)
      - Stop primary if possible (pg_ctl stop -m fast)
      - Promote standby: pg_ctl promote or SELECT pg_promote()
      - Update other standbys: primary_conninfo to new primary
      - Update HAProxy/VIP/pgbouncer
      - Rebuild old primary as new standby using pg_rewind or pg_basebackup
    - pg_rewind
      - Rewind old primary to sync point with new primary
      - Requires wal_log_hints = on or checksums enabled
      - Faster than full pg_basebackup for recently diverged nodes
      - pg_rewind --target-pgdata --source-server="host=new_primary ..."
    - Post-failover validation checklist
      - Verify new primary is accepting writes
      - Verify all standbys connected to new primary
      - Verify replication slots recreated if needed
      - Verify logical replication restarted
      - Verify application connection routing correct
      - Verify monitoring dashboards updated
      - Verify backup jobs pointing to new primary
